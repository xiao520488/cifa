# 内置词库数据（ECDICT → src/data/*.json）

> 一句话：四本内置词库不是手写的，是从 **ECDICT 1.0.28** 的 `ecdict.csv` 生成出来的；
> 改词库 = 跑一次 `node scripts/build-books.ts`，不要手改 JSON。

## 1. 来源与许可

| 项 | 内容 |
| --- | --- |
| 数据集 | ECDICT（skywind3000/ECDICT），tag `1.0.28` |
| 文件 | 仓库根目录的 `ecdict.csv`（约 63MB，770,611 行） |
| 许可 | MIT（仅限学习用途；商用前请看上游 README） |
| 字段 | `word,phonetic,definition,translation,pos,collins,oxford,tag,bnc,frq,exchange,detail,audio` |

`ecdict.csv` **不进仓库**（`.gitignore` 里有 `.tmp-vocab/`）。重新拉取：

```bash
curl -L -o .tmp-vocab/ecdict.csv \
  https://ghfast.top/https://raw.githubusercontent.com/skywind3000/ECDICT/master/ecdict.csv
node scripts/build-books.ts      # 生成 src/data/*.json + books.json
```

`ghfast.top` 是 GitHub 的加速镜像，直连 raw.githubusercontent 时实测只有 18KB/s（63MB 要一小时），
走镜像 50 秒。镜像只影响下载速度，文件内容会校验行数（770,611 行）。

## 2. 四本词库怎么来的

| 文件 | 词库 | 收哪个 tag | 词数 | 音标覆盖 | 词频覆盖 |
| --- | --- | --- | --- | --- | --- |
| `senior.json` | 高中核心词 | `gk`（高考） | 3,671 | 99.0% | 99.5% |
| `cet4.json` | 四级核心词 | `cet4` | 3,846 | 99.7% | 99.6% |

## 3. 字段与清洗规则

产物字段（`src/lib/types.ts` 的 `Word`）：

| 字段 | 含义 | 说明 |
| --- | --- | --- |
| `w` | 单词 | 小写；只留单个英文词（允许 `'` / `-`），短语和带空格的词条全部丢弃 |
| `ph` | 音标 | 统一成 `/…/`；拿不准的宁可为空，也不输出乱码 |
| `m` | 释义 | 1–2 条，`m[0]` 为主义，带词性前缀 |
| `r` | 词频名次 | ECDICT `bnc` / `frq` 取较小值；0 视为没有 |
| `x` | 考试标签位掩码 | `zk=1, gk=2, cet4=4, cet6=8, ky=16, toefl=32, ielts=64, gre=128` |

### 3.1 音标：stardict 的「伪 IPA」要翻译

ECDICT 的音标不是标准 IPA，直接显示会像乱码：

| 源写法 | 含义 | 产物 |
| --- | --- | --- |
| `ә`（西里尔 schwa） | schwa | `ə` |
| `є` / `ε` | /e/ | `e` |
| `:` | 长音符 | `ː` |
| `'` | 主重音 | `ˈ` |
| `,` | 次重音 | `ˌ` |
| `.` | 次重音（词首）或两个读音的分隔 | 见下 |
| `ɒ:` | 实际是 /ɔː/ | `ɔː` |
| `ə:` | 实际是 /ɜː/ | `ɜː` |
| `^` | 源数据坏掉的 /g/ | `g` |
| `(r)` | 可省略音 | 只留 `r` |

- `abuse = ә'bju:s.ә'bju:z`：两边都有重音 → 判定为两个读音，只留第一个。
- `.ækә'demik`：只有一个重音 → `.` 是次重音，输出 `/ˌækəˈdemik/`。
- 清洗后只要还剩不认识字符就整条丢弃（所以有 0.2–1% 的词没有音标，界面会跳过音标行）。

### 3.2 释义：为了「5 词同屏」必须收敛

真实词典释义很长（`in` 有 6 个 prep 义项），照搬会让一行占 3–4 行、一屏放不下 5 个词。规则：

1. `\n` 分条；`[网络]` 开头的众包释义整条丢弃。
2. `[医] [计] [经]` 这类领域标记：**去掉标记保留释义**，但只在「没有任何常规释义」时才用它
   （否则 `it` 的第二义会变成「信息论；输入终端；智能终端」）。
3. `vt. / vi. / v.` 合并成 `v.`；`a. / adj.` → `adj.`；`ad. / adv.` → `adv.`。
4. 同词性的多行合并成一条；最多 2 条（`MAX_SENSES`）。
5. 每条按 `，；、` 切块，最多 3 块（`MAX_FRAGMENTS`），首条 ≤15 字、次条 ≤12 字。

### 3.3 排序：高频优先，但功能词押后

- 主序：`r` 升序（越小越常见）；没有词频的排最后，再按字母序。
- **纯语法功能词（the / be / and / of / in / which / would …）整体押到队尾**。
  它们确实在考纲里，但按词频排的话每本书的头三批全是 `the、be、and`，第一印象就是「词库有问题」。
  不删除（词表要完整），只挪位置。判断刻意保守：`might`（n. 力量）、`will`（n. 意志）、
  `can`（n. 罐头）这类一词多义的不算功能词。名单在 `scripts/lib/ecdict.ts` 的 `FUNCTION_WORDS`。

> 这样做的副作用：调度引擎的「词表顺序」天然就是「高频 → 低频」，不需要开
> `newWordOrder: 'freq'`，也就不必在状态里存 `freqRank`（5000 词约 140KB localStorage）。

## 4. 加载方式：四本词库按需加载

四本合计约 **1.8MB 原始 JSON / 630KB gzip**。全部塞进入口 chunk 会让首屏多背 600KB，
所以改成 `import()` 按阶段懒加载（`src/lib/books.ts`）：

- 首屏只拉当前阶段那一本：`index.js` 100KB gzip + 词库 130–199KB gzip；
- 换阶段时拉另一本；Service Worker 的 cache-first 会把拉过的书缓存下来；
- `src/data/books.json`（构建时生成）只存每本的词数，供「学习阶段」列表在不加载书的情况下显示 3,671 词。

**硬约束**：`App` 挂载前必须 `await preloadBook(当前阶段)`（`src/main.tsx` 的 `<Boot/>` 做的）。
词库没到就挂载的话，调度引擎会拿空词池 `seed([])`，把当天的「新词计划」结算成 0 并落盘——
那个状态修不回来，只能等第二天。

## 5. 「种子池 = 当前词库」怎么保证

`useScheduler` 启动时 `engine.seed(deckWords(book))`，`seed()` 的语义是：
**未学池 = 传入词表 − 已有卡片 − 已归档**。所以：

- 换阶段 / 重新导入 → 池子完全换成新书（已学卡片保留，不在新书里的卡片仍按计划复习）；
- 词库变大变小都不影响已学进度，卡是按**单词字符串**存的，不是按数组下标；
- `scripts/test-books.ts` 用真实 JSON 断言了三条：seed 后池子 = 词数、学过的词被剔除、换书后池子跟着新书走。

## 6. 校验

```bash
node scripts/test-books.ts
```

覆盖：清洗函数单测（音标 11 例 / 释义 7 例 / CSV 2 例）、四本书的结构不变量
（词形、库内去重、音标格式、释义条数与中文、排序、覆盖率）、种子池一致性。

## 7. 已知取舍

- **释义为了排版收敛到 1–2 条**，不是完整词典；想要全义项得另做词条详情页（数据里没保留完整 translation）。
- **音标 0.2–1% 缺失**（约 12–30 词/本），界面会跳过音标行，不影响背诵。
- **没有例句、没有词形变化**（ECDICT 的 `exchange` 列没导入）；发音仍是待办。
- 词表是「考纲 tag + 词频」的组合，不等于官方 3500 / 5500 的逐词清单（官方清单口径每年有出入）。
